# SDLC CLI — детальная спецификация

[SDLC_CLI_SPEC.md](../SDLC_CLI_SPEC.md) задаёт цели, принципы и границы MVP. Документы этого каталога раскрывают её до уровня, по которому можно писать код: схемы данных, алгоритмы, контракты tools, промпты, тесты.

При расхождении действует детальный документ: он уточняет исходную спецификацию, а все отступления перечислены ниже, в журнале решений.

## Документы

| Документ | Содержание |
|---|---|
| [01-policy.md](01-policy.md) | Формат `~/.pi/SDLC.md`: полная схема, defaults, коды ошибок валидации, guards переходов, изменение Policy между запусками |
| [02-storage.md](02-storage.md) | Layout `.sdlc/`, схемы `state.json`, `runs/`, `index.json`, `runtime.json`, каталог событий, атомарная запись и outbox, project lock |
| [03-engine.md](03-engine.md) | Автомат фаз, основной цикл, agent / supervisor / human steps, валидация и применение решений, recovery, сигналы, лимиты |
| [04-agents.md](04-agents.md) | Pi SDK: что используется и почему, `AgentRuntime`, guard-расширение, tools агента и supervisor, evidence refs, шаблоны промптов, redaction |
| [05-cli-ui.md](05-cli-ui.md) | Команды и флаги, меню, экран выполнения, human prompt, неинтерактивный режим, `status`, `doctor`, exit codes |

Порядок чтения для реализации: 03 → 02 → 04 → 01 → 05 → 06. Engine — центр, остальное его обслуживает.

## Границы безопасности MVP

- Дочерний агент — процесс пользователя с `bash`. Guard блокирует `write`/`edit` в `.sdlc/` (кроме `artifacts/`), но не может ограничить shell. Подмена state обнаруживается, но не предотвращается.
- Supervisor не получает `bash`, `edit`, `write` и ничего не запускает. Чтение ограничено project root, git вызывается только фиксированными read-only командами.
- Секреты не попадают в журнал (redaction), окружение не пишется в `.sdlc`. Ответы человека сохраняются дословно: это доказательство approval.
- Необратимые действия (push, деплой, сообщения в Slack) регулируются только Policy и guards. CLI их не распознаёт.

## Принятые решения

| # | Вопрос | Решение (2026-10-24) |
|---|---|---|
| Q1 | Прямой диалог дочернего агента с пользователем | `ask_user` остаётся (D4); его можно выключить в Policy через `askUser: false` |
| Q2 | Процесс описан в глобальном `~/.pi/agent/AGENTS.md` | Процессную часть переносим в `~/.pi/SDLC.md` (черновики: [examples/SDLC.md](../examples/SDLC.md), [examples/AGENTS.md](../examples/AGENTS.md)). В `AGENTS.md` остаются только общие правила окружения: секреты, контейнеры, запрет установок. Поэтому по умолчанию дочерние агенты подгружают его (`contextFiles: inherit`), supervisor — нет. Расширения подгружаются у всех: через них подключены провайдеры моделей `claude-code` и `antigravity` (01 §2.7) |
| Q3 | Версия Pi | Локальный `pi` обновлён через Homebrew до 1.4.0, SDK фиксируется на той же 1.4.0. Дальше CLI и SDK обновляются вместе. Расширение `herdr-agent-state.ts` совместимо: события `session_start`, `agent_start` и `agent_settled` в 1.4.0 есть |
| Q5 | Запуск команд supervisor-ом | Supervisor сам ничего не запускает, кроме дочерних агентов (через управляющие решения). Проверки с запуском поручаются агенту этапа (D19) |
| Q6 | Язык | Интерфейс и промпты на русском: system prompt, prompts, описания и ответы tools. Латиницей только идентификаторы (04 §7) |
| Q8 | Ожидание внешних событий (ответ ревьюера, pipeline, сборка) | Нужна отложенная перепроверка для ревью и для feature testing (D23). Ревьюер — агент и отвечает в течение 15 минут; тестирование занимает 1–8 часов, поэтому в `examples/SDLC.md` после выкладки добавлен этап `feature_testing`: тред в канале QA, регрессионные автотесты от QA-агента и второй approve QA-инженера в MR. Supervisor вызывает `schedule_recheck`, CLI в нужный момент сам продолжает агента этапа. Ожидание работает, пока запущен `sdlc`; без открытого терминала задачу можно будить через `sdlc resume KEY --no-wait` из cron |
